同一份拓扑，生成多份变形 CLAS

这节课沿着 NVIDIA 示例追踪两组数据：初始化时构建的模板和每帧生成的 CLAS。最后用 LearnVulkan2 的接口绑定它们的存储与地址表。

依据本地 E:/GitStorage/nvidia_examples/v2/vk_animated_clusters。阅读约 8 分钟；代码位置均指本地版本。

1. 先把四种东西分开

设一个 cluster 的三角形始终是 (0,1,2) 和 (2,1,3)。动画只改变这四个顶点的位置。驱动可以预先完成不依赖最终位置的工作，把结果放进 template；每帧再结合当前顶点生成 CLAS。这是扩展的设计动机。[Khronos 设计说明]

索引 / 固定属性→Template＋ 当前顶点 →CLAS→Cluster BLAS→TLAS
对象在本例中的作用动画期间
Template保存拓扑相关的预计算和继承属性跨帧、跨同 geometry 的实例复用
CLAS当前顶点位置对应的 cluster 加速结构通过模板重新实例化
Cluster BLAS引用一组 CLAS 地址CLAS 改变后重建
TLAS引用 BLAS 并提供实例变换示例在 BLAS 地址回填后 build/update

Template 本身不能交给 BLAS，也不能直接追踪。实例化输出才是普通的 CLAS。[Template API] 在这个动画示例里，每次都提供当前顶点；把实例化理解为一次优化过的 CLAS 生成过程，而不是旧 CLAS 的 refit。

假设同一个 geometry、每个实例独立变形、每个实例一个 BLAS。静态共享路径和多帧并行存储另计。示例按 geometry 的每个 cluster 建模板，没有自动把不同 geometry 的相同拓扑去重。

2. 初始化：先建模板，再给未来 CLAS 留空间

主文件是 src/renderer_raytrace_clusters.cpp。入口 482–485 依次调用 initRayTracingTemplates() 和 initRayTracingTemplateInstantiations()。

第一步，构建模板。508 行开始，为每个 geometry 的每个 cluster 填一条 VkClusterAccelerationStructureBuildTriangleClusterTemplateInfoNV：

// 结构示意；省略了 flags、对齐与预算检查。
templateTask.clusterID = c;
templateTask.triangleCount = cluster.numTriangles;
templateTask.vertexCount = cluster.numVertices;
templateTask.indexBuffer = clusterIndices;
templateTask.vertexBuffer = referencePositions;
templateTask.instantiationBoundingBoxLimit = boundsAddress;
// opType = BUILD_TRIANGLE_CLUSTER_TEMPLATE_NV

这里的参考顶点可以帮助构建器组织三角形；动画实例化仍使用当前顶点。索引固定意味着顶点编号的意义也必须保持。例如模板索引 3 对应实例顶点表中的同一个逻辑顶点，不能只保证顶点数量一样。

示例提供两条模板分配路径：隐式构建到临时块，再用 MOVE_OBJECTS 紧凑搬运；或者先用 COMPUTE_SIZES 查询模板大小，再显式构建到最终地址。初学时重点看后者：717–720、793–810 行。

第二步，查询实例化后 CLAS 的大小。813–867 行把 opType 换成 INSTANTIATE_TRIANGLE_CLUSTER_NV，opMode 设为 COMPUTE_SIZES_NV。示例把查询任务的顶点地址设为 0，取得不依赖实际动画顶点的保守实例化大小。它不是在这个步骤生成 CLAS，也不意味着实际动画实例化能省掉顶点。

两次大小不能混用：
模板大小 → 给共享的 Template Buffer 分配空间。
实例化大小 → 给每个变形实例的 CLAS Buffer 分配空间。
Host 的 vkGetClusterAccelerationStructureBuildSizesNV 负责预算 / scratch；GPU 的 COMPUTE_SIZES 利用具体任务获得更紧的大小界。

第三步，准备固定的任务与输出地址。879–999 行，为每个动画实例分配 CLAS 输出 Buffer，并缓存以下数据：

task.clusterTemplateAddress = templateAddresses[c];
task.clusterIdOffset = 0;
task.geometryIndexOffset = 0;
task.vertexBuffer.startAddress = instancePositions + localVertexOffset;
task.vertexBuffer.strideInBytes = sizeof(glm::vec3);

clasDstAddresses[i] = instanceClasBufferBase + instantiationOffsets[c];

instantiationOffsets 是每个 CLAS 预留大小的前缀和。若模板、顶点 Buffer 的地址和布局稳定，任务也能跨帧复用：每帧改的是顶点内容。轮换不同的顶点 Buffer 时，要相应选择或更新任务里的地址。

注意索引空间：独立 cluster 顶点路径使用 8 位局部索引，顶点地址需要加 firstLocalVertex 偏移；共享顶点路径使用全局 32 位索引，顶点地址使用整块 positions 的起点。参见 666–683 与 971–982 行。

3. 每帧：实例化命令到底读写什么

360–388 行的关键操作可以缩成下面这段。名称仍是 Vulkan 类型；这是字段关系示意，不是可直接编译的完整程序。

inputs.opType = VK_CLUSTER_ACCELERATION_STRUCTURE_OP_TYPE_INSTANTIATE_TRIANGLE_CLUSTER_NV;
inputs.opMode = VK_CLUSTER_ACCELERATION_STRUCTURE_OP_MODE_EXPLICIT_DESTINATIONS_NV;
inputs.maxAccelerationStructureCount = totalClusters;
inputs.opInput.pTriangleClusters = &triangleLimits;
inputs.flags = instantiateFlags;

cmdInfo.input = inputs;
cmdInfo.srcInfosArray = tasksRegion;          // GPU 中的实例化任务数组
cmdInfo.dstAddressesArray = clasDstRegion;   // 预先填好的 CLAS 目标地址数组
cmdInfo.scratchData = scratchAddress;
vkCmdBuildClusterAccelerationStructureIndirectNV(cmd, &cmdInfo);

EXPLICIT 模式会读取目标地址数组，把 CLAS 写到那些地址。IMPLICIT 模式则在提供的存储块里安排输出并写回地址表。两者都不会替应用分配一块新的 VkDeviceMemory。[模式定义]

原地覆盖的前提：必须先让所有读取旧 CLAS 的 GPU 工作完成，包括通过旧 BLAS / TLAS 进行的遍历。BLAS 引用 CLAS 存储，不会保存一份旧内容。下面的帧内流程还需要跨帧的“旧遍历读取 → 新实例化写入”依赖；容量和地址固定并不保证并发安全。

完整依赖链见 283–357 行。BLAS 输入在 1193 行指向 CLAS 地址表；显式地址没变，也不代表 CLAS 的包围信息没变，仍须重建依赖的 BLAS。

同一 queue 可用适当 stage 范围的 barrier 排序旧遍历与新构建，跨 queue 则需要 semaphore 依赖及必要的所有权转移。如果想让旧版本遍历和新版本构建重叠，给它们分别保留 CLAS 及相应的 BLAS / TLAS 存储；复用一个 frame slot 前，等覆盖该 slot 全部使用的完成信号。只读模板可以共享。

如果 GPU 生成任务或 count，要把写入同步到 AS_BUILD 阶段的 INDIRECT_COMMAND_READ；这个输入访问和顶点读取不能混为一谈。scratch 的复用也需要同步。参见 命令同步规则。

4. BBox 是你对未来变形的承诺

instantiationBoundingBoxLimit 不为 0 时，后续实例化的顶点必须落在给定范围内。范围太小，未来动画可能违反约束；不确定范围时可不提供这个限制。[字段定义]

示例 639–655 行实际这样膨胀：

bloat = length(geometry.bbox.hi - geometry.bbox.lo) * templateBBoxBloat;
clusterBBox.lo -= bloat;
clusterBBox.hi += bloat;

它用的是整个 geometry 的 bbox 对角线长度，不是每个 cluster 自身尺寸的百分比。限制处于传入顶点的坐标空间；TLAS 的物体世界变换不要求把这个框也扩到世界空间。

positionTruncateBitCount 会舍弃 float 位置的低位以改善压缩，是精度与存储之间的权衡。开始验证时可用 0，再用误差与性能测量决定是否增加。BBox 和目标地址的对齐应查询设备属性，不能把样例的具体字节数当成所有设备的常量。

5. 在 LearnVulkan2 中绑定模板和实例化命令

用 ClusterLevelAccelStructBuildLimits 给出单个目标和整条命令的三角形、顶点预算。maxCount 是一条命令的最大任务数。调用方按所选操作与模式查询容量和对齐，分配 Buffer，再把地址传给命令。

阶段RHI 操作
模板分配调用 ImplicitClusterAccelStructCommandInput::GetClusterTemplateMemoryRequirements(limits, maxCount)，按返回值分配模板存储和 scratch，另备 maxCount 个连续的 VkDeviceAddress 作为输出表。
构建模板SetClusterTemplateTarget(limits, maxCount, storageAddress, outputReferencesAddress) 绑定隐式目标。任务使用 ClusterLevelAccelStructTemplateBuildInfo 的 GPU 布局。构建完成并同步后，从地址表读取模板地址。
实例化 CLAS每个 ClusterLevelAccelStructInstantiateBuildInfo 任务提供模板和当前顶点的地址。SetInstantiateClusterTarget 支持 Compute Sizes 写逐目标大小、Explicit 读目标地址表、Implicit 写入连续存储并输出地址表。
构建 Cluster BLASSetClusterReferences(referenceAddress, count) 描述一个 BLAS 读取的 CLAS 地址切片。SetBottomLevelAccelStructTarget 绑定整批 BLAS 的预算、数量上限和目的地址。
RT pipeline在 Finalize() 前设置 CustomizeAllowClusterAccelerationStructure(true)，再创建用于追踪这些结构的 Program。

任务可由 GPU 生成，也可通过各任务类型的 CommitToDeviceInline 从 CPU 上传。通过 SetArgumentAddress 和 SetScratchAddress 绑定任务和临时存储。可选的 CustomizeOperationCountAddress 指向 GPU 实际任务数，生产者保证其不超过 maxCount，消费者只读取本次生成的有效前缀。省略计数地址时，所有 maxCount 条记录都必须有效。

BLAS 构建读取 CLAS 地址表，该表需保留到构建读取完成。底层 CLAS 存储需保留到所有引用它的 BLAS 最后一次 GPU 使用完成，包括经 TLAS 的遍历。模板存储保留到最后一次依赖它的实例化或模板查询完成。任务、顶点和 scratch 各自保留到其最后一个 GPU 消费者完成。RHI 示例 · 资源生命周期。
