场景只动了一小块，TLAS 要做多少工作？

目标：给定实例变化的空间分布，能解释 PTLAS 复用了什么，并判断它是否值得做性能原型。

承接 Cluster Template。本课聚焦原理与接入价值，不修改引擎实现。约 6 分钟。

1. 从物体内部，走到整个世界

上一课把物体内部的几何工作拆成可复用的 cluster；PTLAS 把场景中的实例分组，保留未变化组的加速结构。CLAS 与 PTLAS 可以独立使用：普通三角形 BLAS 也能放进 PTLAS。[Microsoft 原文]

把城市分成街区：大多数街区静止，一处街区有物体移动。应用给实例指定 partitionIndex，驱动维护每个分区的内部结构，再把分区组织进上层结构。空间网格只是分组方案之一，不是 API 的强制要求。[Khronos 设计]

一个 PTLAS→A 分区：复用B 分区：有变化，重建C 分区：复用

这是一个 PTLAS 的内部组织方式，不需要应用把几个可独立追踪的 TLAS 手工嵌套起来。光线最终仍通过实例访问 BLAS。

普通 TLAS 已有 refit / update 路径；因此不要把比较简化为“普通 TLAS 每帧一定从零重建”。关键差别是：常规接口提交整个实例集合，PTLAS 提交持久状态上的稀疏改动。[NVIDIA 示例说明]

2. 这一帧的写入数组，不等于完整场景

可以把 PTLAS 理解成持久实例表加上缓存的分区结构。instanceIndex 标识表中的槽位，partitionIndex 标识所属分区，两者都不是本帧写入数组的下标。[WRITE 数据]

初始化：写入实例 0 … N-1，建立 PTLAS
下一帧：只写入 instanceIndex = 37、9002 的完整记录
         其余实例保留以前的记录
         受影响的普通分区重建，上层组织相应维护

迁移一个实例时，旧分区失去它，新分区得到它，两边都可能产生维护成本。持久记录和局部分区复用见 DXR 规范。

核心判断：变化实例少，并不自动等于变化分区少。还要观察这些实例散布在哪里。

教学例子：100 万实例，分成 1,000 个普通分区，每区 1,000 实例；只考虑 transform 的完整写入。

本帧变化受影响普通分区推断
10 个实例，都在同一分区1 个大量分区可复用
10 个实例，分别在 10 个分区10 个相同写入数量，牵动更多分区
1,000 个实例，每区一个1,000 个变化只有 0.1%，仍触及所有普通分区

这是推理模型，不是 GPU 时间预测。还需计入上层组织维护、global 实例、命令生成及实际驱动算法；不能据此声称严格 O(变化实例数)。

3. 为什么还有 global partition？

假设每个静态街区里都有一辆每帧移动的汽车。把它们一直留在普通分区，会频繁牵动很多街区。global partition 中的实例在构建和遍历上按“各自一个分区”处理，因此适合持续活动的实例；稳定后可移回空间上合适的普通分区。它有自己的容量预算。[Khronos 设计]

代价是上层需要处理更多独立项。分组越细，局部重建通常越省，但遍历不一定越快；分区包围盒彼此重叠也会影响遍历。NVIDIA 多米诺示例提供原地更新、移入 global，以及根据相机距离混合选择的模式，适合观察这个取舍。

4. 三个操作，先记对移动用哪个

操作用来做什么
WRITE_INSTANCE完整写入实例；transform 改变或更换分区都走这里。字段
UPDATE_INSTANCE只修改 BLAS 地址和 hit-group 索引贡献，不修改 transform；适合符合约束的 LOD / BLAS 替换。字段
WRITE_PARTITION_TRANSLATION（Vulkan）设置整个分区的额外平移，例如大世界原点调整；需要启用该功能。DXR 名为 TRANSLATE_PARTITION。字段

UPDATE 不意味着“任意更新都便宜”。DXR 显式 AABB 开启后，替换 BLAS 的变换后边界必须仍在声明范围内；未显式指定时，边界扩张可能触发 refit。范围预留越松，也可能增加遍历工作。[DXR 约束]

分区平移可以让实例变换保留为分区相对坐标，再附加分区平移。它不是任意旋转 / 缩放的多级实例化接口。[平移语义]

5. 判断引擎是否值得接入

把它当作需要验证的假设：大量实例、较多静态区域、变化集中或动态实例可隔离时，PTLAS 有机会节省场景更新成本。若每帧几乎所有分区都变，或者 TLAS 时间本来很小，就不应仅凭实例数量决定。

比较同样场景、同样光线负载下的 GPU 时间：
变化检测 / 参数生成 + AS build/update + trace

同时记录：变化实例数、受影响分区数、global 实例数、AS / scratch 内存

分别测试稀疏集中、稀疏分散和大面积动态，比较普通 TLAS rebuild、允许时的 refit，以及不同分区粒度的 PTLAS。以上是实验建议，不是已经测得的收益。

当前本仓库 src 未检索到 PTLAS 特性或构建接口；已有 CLAS 支持不能自动提供 PTLAS。接入面至少包括能力查询、容量与存储、间接写入命令、descriptor，以及同步 / 生命周期。Vulkan 的入口是 vkCmdBuildPartitionedAccelerationStructuresNV，descriptor 也有独立类型。[命令] [绑定]

Vulkan 预算包含总实例、普通分区、单分区实例与 global 容量，不能只按当帧写入数分配。[预算字段] PTLAS 更新仍需服从旧遍历到新写入的依赖；原地更新时尤其不能覆盖正在被 GPU 读取的存储。scratch、间接输入和 AS 结果各有同步要求。[同步规则]
